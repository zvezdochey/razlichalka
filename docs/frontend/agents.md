# Сабагенты фронта

Чтобы основная сессия Claude Code не забивалась мусором (поиск по файлам, промежуточные
попытки, логи браузера), фронтовая работа разбита на 4 саб-агента. Каждый работает в своём
отдельном контексте и возвращает в основную сессию только итог.

Файлы лежат в `.claude/agents/` (подхватываются Claude Code автоматически, если открыть
сессию из корня репозитория).

## Состав и порядок вызова

Обычный цикл на одну фичу (одну ветку `front/...`):

```
react-coder  →  ui-designer  →  browser-tester  →  code-reviewer-front  →  PR
```

Перед крупными развилками (не для каждой мелкой фичи) добавляется ещё один шаг в начале:

```
planner  →  react-coder  →  ui-designer  →  browser-tester  →  code-reviewer-front  →  PR
```

| Агент | Файл | Что делает | Инструменты |
|---|---|---|---|
| **`planner`** | `planner.md` | Разбивает крупную задачу (несколько ручек/экранов, нет очевидной структуры) на шаги/ветки, без написания кода | Read, Grep, Glob |
| **`react-coder`** | `react-coder.md` | Пишет сам код фичи строго по контракту `docs/api.md`: компоненты, запросы к бэку, типы | Read, Write, Edit, Bash, Grep, Glob |
| **`ui-designer`** | `ui-designer.md` | Полирует визуал/UX уже рабочего экрана (цвета, расположение, типографика), **не трогая логику**. Использует скил `frontend-design` | Read, Edit, Grep, Glob |
| **`browser-tester`** | `browser-tester.md` | Реально открывает сайт в браузере, проходит сценарий, смотрит консоль на ошибки, делает скриншот. Использует скил `webapp-testing` | Read, Bash, Grep, Glob |
| **`code-reviewer-front`** | `code-reviewer-front.md` | Финальная проверка диффа перед PR: типы, безопасность, читаемость, соответствие контракту | Read, Grep, Glob, Bash |

## Почему именно так разбито

- **`react-coder` ≠ `ui-designer`**: реализация логики и визуальный полиш — разные задачи с
  разным риском. Полиш не должен случайно задеть рабочую логику, поэтому у него нет доступа
  на запись в произвольные места (`Write` не дан, только `Edit`).
- **`browser-tester`** — обязателен перед тем, как сказать «готово»: «код скомпилировался»
  не значит «работает». У агента минимальный набор инструментов — ему не нужно писать код.
- **`code-reviewer-front`** — последний барьер перед PR, который смотрит капитан. Чем чище
  приходит PR, тем быстрее Семён его смержит.

## `planner` vs встроенный Plan Mode

Это не одно и то же:

- **Plan Mode** (встроенный режим Claude Code) — обсуждение плана прямо в основной сессии,
  интерактивно. Разведка по файлам/документации идёт в общем контексте. Подходит для
  **мелких понятных фич** — быстрее, чем вызывать агента.
- **`planner`** — отдельный контекст, сам читает `docs/api.md` и код, возвращает готовый план
  без разведки в основной сессии. Вызывается **только перед крупными развилками** (новый
  большой кусок экрана, решение про стейт-менеджмент и т.п.) — не на каждую ветку.

Решение, который из двух использовать, принимается по месту — не формализовано отдельным
правилом, кроме как «мелкое — Plan Mode, крупное и затратное на разведку — `planner`».

## Чего нет и почему

Не стали делать отдельного «api-агента» для интеграции с бэком — это естественная часть
работы `react-coder`, дробить дальше было бы избыточно для масштаба хакатона (одна фронтовая
голова, короткие сроки). Если команда вырастет или фронта станет сильно больше — можно
выделить отдельно.
