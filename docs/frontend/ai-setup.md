# ИИ-настройки фронта: MCP, плагины, скилы

Это справка по тому, чем пользуется Claude Code при работе над `frontend/`. Если фронтом
занимается не Саня (например, подключился Илья, или ты продолжаешь его работу) — поставь
то же самое, чтобы получить тот же уровень автоматизации.

Общее правило команды (см. `docs/ai-tools.md`): ставим только официальное от Anthropic/OpenAI
и скилы из `obra/superpowers` (MIT) — непроверенные плагины не ставим, это чужой код,
который выполняется на твоём ноуте.

---

## MCP-серверы

Настроены в `.mcp.json` (общий для всей команды, уже в репозитории):

- **Context7** — отдаёт свежую документацию по библиотекам (React, Vite, любые npm-пакеты),
  чтобы Claude не выдумывал API по старой памяти.
- **Playwright** — даёт Claude реально открывать сайт в браузере: кликать, вводить текст,
  смотреть консоль, делать скриншоты.

Проверить, что оба подключены: команда `/mcp` в Claude Code.

**Нюанс с браузером:** Playwright по умолчанию целится в Chrome. Если на машине нет Chrome
(как было у Сани), он не запустится с ошибкой `Chromium distribution 'chrome' is not found`.
Решения:
1. Поставить Google Chrome — тогда всё работает из общего `.mcp.json`, ничего менять не надо.
2. Либо переключить Playwright на Firefox **лично для себя** (не трогая общий `.mcp.json`,
   чтобы не сломать тех, у кого Chrome есть):
   ```
   claude mcp add playwright --scope local -- npx -y @playwright/mcp@0.0.84 --browser firefox
   ```
   (версия `@0.0.84` должна совпадать с той, что в `.mcp.json` — проверь перед тем как копировать)
   и затем поставить сам браузер под именно эту версию MCP-пакета:
   ```
   npx -y @playwright/mcp@0.0.84 install-browser firefox
   ```
   Важно ставить браузер именно через `@playwright/mcp`, а не через голый пакет `playwright` —
   у них разные версии Firefox под капотом, и обычный `npx playwright install firefox`
   скачает не ту версию, которую ищет MCP-сервер.
3. После любого из вариантов — **перезапусти Claude Code**, чтобы подключение подхватилось.

## Плагины (`claude plugin install <имя>@claude-plugins-official`)

| Плагин | Что делает | Зачем на фронте |
|---|---|---|
| `frontend-design` | Помогает делать интерфейс не шаблонным — направление по эстетике, типографике | Чтобы UI не выглядел дефолтным Bootstrap-ом |
| `typescript-lsp` | TypeScript language server — ошибки типов видно сразу, без отдельной компиляции | Меньше багов из-за несовпадения типов с `docs/api.md` |
| `security-guidance` | Предупреждает про потенциально дырявый код в правках | На случай XSS/небезопасного рендера пользовательских данных |
| `commit-commands` | Коммит + push + PR одной командой | Экономит время на рутине git — коммитить придётся часто |
| `code-simplifier` | Чистит/упрощает код для читаемости, не меняя поведение | Код должен быть понятным — его объясняют жюри |

Установлены со scope `user` — то есть не завязаны на конкретный проект, будут везде на этой машине.

## Скилы

- **`webapp-testing`** (`anthropics/skills@webapp-testing`) — тулкит для запуска локального
  сайта и проверки через Playwright: скриншоты, консоль браузера, клики. Установлен **локально
  в проект** (`.agents/skills/webapp-testing`, `.claude/skills/webapp-testing`) — не плагин,
  поэтому команда установки другая:
  ```
  npx -y skills add anthropics/skills@webapp-testing
  ```
- **`systematic-debugging`** — приходит в комплекте с плагином `superpowers`, отдельно
  ставить не нужно, если `superpowers` уже установлен.

## Чего не ставили и почему

- `theme-factory` (`anthropics/skills`) — генерация палитры/темы. Пересекается с тем, что уже
  умеет `frontend-design`, решили не дублировать.
- Любые плагины не от Anthropic/OpenAI из общего маркетплейса (их там десятки — языковые
  сервера для других стеков, интеграции с базами, сторонние security-сканеры и т.п.) —
  не подходят по правилу команды «только официальное + superpowers».
