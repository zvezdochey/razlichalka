# E15. В сводной — только заявки, которые есть в обоих срезах

**Кто:** Егор · **Ветка:** `egor/paired-apps-only` · **Папка:** `backend/pipeline/`, `backend/app/services/` + `docs/api.md` п. 7.1 · **Зависит от:** E9 · **Время:** ~1 час, между E10 и E11

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/egor/E15-paired-apps-only.md`. Сначала прочитай `AGENTS.md`, `docs/api.md` (п. 7.1–7.4) и `backend/pipeline/compare.py`, `backend/pipeline/summary.py`.»

## Зачем
Орги в чате ответили: если ответа по заявке нет или он не прошёл разбор (сломанный JSON), строку для неё можно не создавать.
Об отсутствии скажет автопроверка или счётчики в сводке. **«В сводной таблице правильнее анализировать только заявки,
где данные есть в обоих срезах — before и after. Остальные исключить.»**

Сейчас `compare.py` делает outer join по строкам атрибутов, и заявка, которой нет в одном срезе, попадает в сводную
целиком как `ATTRIBUTE_NEW` / `ATTRIBUTE_LOST`. Это шум, из-за него завышены `applications_changed` и `attributes`.

## Что сделать
1. Определить множество заявок, у которых есть строки **и в BEFORE, и в AFTER** (по `APP_ID` после нормализации).
2. Витрина (`compare.py`) и всё, что считается по ней (`summary`, `facts`, `apps`), работает только с этими заявками.
   Заявки без пары в витрину не попадают.
3. Посчитать исключённые и отдать счётчиками в `GET /api/runs/{id}/summary` (поля уже вписаны в `docs/api.md` п. 7.1):
   - `applications_only_before` — есть только в BEFORE;
   - `applications_only_after` — есть только в AFTER;
   - `applications_total` не меняем смысл: это заявки с парой.
4. Записать счётчики в журнал этапа сравнения (`log("warn", ...)`), если они ненулевые.
5. Тесты: на маленьком наборе — заявка только в BEFORE, только в AFTER, в обоих; на настоящем датасете счётчики сходятся
   (`applications + only_before + only_after` = все заявки из обоих срезов).

## Готово, когда
- В `facts`, `apps` и `summary` нет заявок без пары.
- `summary` отдаёт `applications_only_before` и `applications_only_after`.
- Тесты бэка зелёные; цифры до и после правки — в описании PR.
