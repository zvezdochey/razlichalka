# E10. «Логика или данные»: откуда взялась смена решения

**Кто:** Егор · **Ветка:** `egor/logic-vs-data` · **Папка:** `backend/pipeline/`, `backend/procedures/` + `docs/api.md` п. 7.1, 7.4 · **Зависит от:** E9

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/egor/E10-logic-vs-data.md`. Сначала прочитай `AGENTS.md`, `docs/tasks/CONTRACTS.md`, `docs/api.md` (п. 7.1, 7.4), `ПАКЕТ/ЗАДАНИЕ/docs/ФОРМАТ_ОТВЕТА.md` (особенно «Три этапа скоринга») и `ПАКЕТ/ЗАДАНИЕ/docs/ГЛОССАРИЙ.md`.»

## Зачем
Сценарий 4 ТЗ: «Это из-за изменения логики или из-за входных данных?». В плане организаторов это прямо названо
**маркером понимания задачи**: в данных есть заявки, где решение изменилось не из-за правки логики, а потому что
внешний источник вернул другое значение. Для аналитика это ложная тревога. Команда, которая это отделила, —
поняла, зачем всё делается.

## Как думать
Ответ СПР состоит из того, что **пришло на вход** (данные заявки, `ext_data[]` — сырые ответы внешних источников),
и того, что **посчитала логика** (`decisionResult.*`: характеристики, скоринг, стоп-факторы, пороги, решение).
`ФОРМАТ_ОТВЕТА.md`, «Три этапа скоринга»: одно и то же число (`score_okb`) лежит и во входе, и в характеристиках,
и в фичах модели. Если оно поменялось **во входе** — изменение пришло снаружи.

Для заявки со сменой решения:

| Входы различаются? | Логика различается? | `CHANGE_SOURCE` |
|---|---|---|
| нет | да | `logic` — изменение из-за новой версии СПР |
| да | — | `data` — входные данные другие (ложная тревога для проверки логики) |
| да, но решающие поля поменялись сильнее, чем объясняется входом | да | `both` |
| нет | нет | `none` (на смене решения быть не должно — если есть, это находка, залогируй) |

Начни с простого правила: «есть различия (`DIFF_FLAG=1`) в путях входа» → `data`, иначе `logic`. `both` — если
успеешь придумать честный критерий; не успеешь — не выдумывай, оставь два значения и напиши это в `api.md`.
Технические поля из `ignore_paths` не считаются.

## Тесты
- Мини-фикстура: заявка, где поменялся только `ext_data[]…score` и решение → `data`; заявка, где поменялся только
  порог → `logic`; заявка без смены решения не попадает в `change_sources`.
- Сумма `change_sources` = `decision_changed`.
