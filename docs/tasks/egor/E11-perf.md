# E11. Замеры и одно ускорение

**Кто:** Егор · **Ветка:** `egor/perf` · **Папка:** `backend/pipeline/` (+ `backend/app/services/` с согласия Семёна) · **Зависит от:** E9; для замера `/facts` — I1

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/egor/E11-perf.md`. Сначала прочитай `AGENTS.md`, `docs/tasks/CONTRACTS.md` и раздел «Планки по времени» в `02_ОПИСАНИЕ_ЗАДАЧИ.md`.»

## Зачем
Шаг 9 демо: «что замеряли, где оказалось узкое место и что дало ускорение». ТЗ: «внятное объяснение весит
больше, чем красивая цифра»; абсолютные секунды между командами не сравнивают. Наивная однопоточная реализация
по ТЗ проходит датасет примерно за 5 секунд — значит, различать команды будет **отклик отчёта** поверх 290 тыс. строк.

Планки ТЗ (минимум / хорошо / отлично): открытие сводной ≤ 5 / 2 / 0,5 с; смена раскладки, фильтр, переход к заявке
≤ 5 / 1 / 0,3 с; повторное открытие готового отчёта ≤ 5 / 1 с / мгновенно.

## Что сделать
1. **Скрипт `backend/pipeline/tools/bench.py`** (запуск `python -m pipeline.tools.bench <датасет>`):
   - время каждого шага конвейера: `normalize` BEFORE, `normalize` AFTER, `compare`, `segments`, `summary`;
   - время ответа ручек на готовом запуске (через `TestClient` или `httpx` к живому бэку), **первый и повторный**
     вызов: `/summary`, `/apps?size=500`, `/apps?decision_change=approve_to_reject`, `/apps/{id}/attributes`,
     `/facts?dims=PATH,CHANGE_TYPE`, `/facts?dims=ARRAY_KEY_1`, `/report`;
   - вывод — таблица markdown, сверху железо (`platform`, `os.cpu_count()`, память).
2. **Найти узкое место** — по таблице, а не по ощущениям. Вероятные кандидаты:
   - `normalize` двух срезов идёт последовательно → два среза параллельно или `ProcessPoolExecutor` по файлам
     (4004 файла — хорошо делится; прогресс `on_progress` и отмена `is_cancelled` должны продолжить работать);
   - первый вызов ручки читает CSV на 290 тыс. строк (`lru_cache` в `results.py` спасает только повторный) →
     прогреть кэш сразу после `ready` или хранить `comparison` в `parquet`/`feather` рядом с CSV (CSV остаётся
     форматом витрины, это только кэш).
3. **Сделать одно ускорение** там, где узкое место, и замерить «до / после» на той же машине.
   Ускорение в `app/` (прогрев кэша, parquet) — согласуй с Семёном, это его папка.
4. **Результат** — таблица «шаг — до — после — машина» в `docs/perf.md` и коротко Семёну для
   `docs/ARCHITECTURE.md` (S12). Плюс одна фраза для защиты: «узким местом было X, сделали Y, стало Z».
