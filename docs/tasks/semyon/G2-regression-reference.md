# G2. Регрессия на эталон организаторов

**Кто:** Семён · **Ветка:** `semyon/regression` · **Папка:** `backend/tests/` · **Зависит от:** G1 (для проверки через Docker) · **Время:** ~45 мин

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/semyon/G2-regression-reference.md`. Сначала прочитай `AGENTS.md`, `docs/tasks/GAPS-7nov.md`, `docs/api.md` (п. 5, 7.1).»

## Зачем
Число заявок с различиями — главный критерий приёмки (ТЗ, «Приёмка»). Сейчас его проверяем руками. Перед защитой любой «зелёный» коммит
может сдвинуть цифру, и никто не заметит.

## Что сделать
1. Тест, который поднимает прогон на датасете из `DATASETS_DIR` (или пропускает тест, если датасета нет) и сравнивает
   `GET /api/runs/{id}/summary`:
   - `applications` = 2002,
   - `applications_changed` = 502,
   - `decision_changed` = 385,
   - `decision_changes`: `approve_to_reject` = 273, `reject_to_approve` = 112.
2. Эталон **не коммитим**. Числа зашиваем в тест, файлы эталона читать не нужно.
3. Тест помечаем маркером `slow` и запускаем отдельной командой; в `backend/pytest.ini` — описать.
4. Если тест падает — не подгонять числа. Сообщить владельцу последнего коммита в `backend/pipeline/`.

## Готово, когда
`pytest -m slow` зелёный на текущем `main`; в `README.md` (раздел тестов) одна строка, как запустить.
