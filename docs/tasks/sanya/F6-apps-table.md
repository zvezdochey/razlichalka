# F6. Вкладка «Заявки»: таблица с фильтрами

**Кто:** Саня · **Ветка:** `front/apps-table` · **Папка:** `frontend/` · **Зависит от:** F4

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/sanya/F6-apps-table.md`. Сначала прочитай `AGENTS.md`, `docs/api.md` (п. 7.4) и `frontend/DESIGN.md` (п. 8, 11).»

## Зачем
Переход от числа к заявкам: список с решением до/после и числом изменённых атрибутов.

## Что сделать (`/runs/:id` → «Заявки», данные — `GET /apps`)
1. Фильтры над таблицей, их состояние лежит **в URL** (`?decision_change=…&search=…&sort=…&page=…`) — ссылкой можно поделиться, «назад» работает:
   - «Решение»: мультивыбор `approve → reject`, `reject → approve`, `решение то же`, `другое`;
   - переключатель «Только с различиями атрибутов» (`has_attr_change=1`);
   - поиск по `APP_ID` и разрезам с задержкой ввода ~300 мс;
   - активные фильтры показаны чипами с «×» и кнопка «Сбросить».
2. Таблица (плотная, 1366 px): `APP_ID` (monospace), `Решение` (`approve → reject` бейджами), `Изменено атрибутов` (число, выровнено вправо, сортируемая колонка), `Модель до → после` (подсвечена, если отличается), `Порог до → после`, `Причина отказа до → после`. Шапка таблицы закреплена, прокрутка внутри области. Пустые значения (`null`) — «—».
3. Сортировка кликом по заголовку (`sort=-attributes_changed` и т.д.): стрелка в заголовке, `aria-sort`.
4. Пагинация: `page`, `size` 50 (выбор 50/100/200), «Показано 1–50 из 273».
5. Строка кликабельна и доступна с клавиатуры (Enter) → открывает панель заявки (F7). Пока F7 нет — просто выставляет `?app=<id>` в URL.
6. Состояния: загрузка (скелетон), ошибка (`ErrorBox` и «Повторить»), «Ничего не найдено» с кнопкой «Сбросить фильтры».
7. Ссылка «Скачать CSV» неактивна с подписью «скоро» (ручка — после MVP).

## Готово, когда
Фильтры/поиск/сортировка/пагинация работают на моках и настоящем бэке; URL восстанавливает состояние после перезагрузки; нет лишних запросов при каждом нажатии клавиши. Проверено `browser-tester`, консоль чистая.
