# F4. Список прогонов и экран выполнения (журнал этапов)

**Кто:** Саня · **Ветка:** `front/run-progress` · **Папка:** `frontend/` · **Зависит от:** F1, F2

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/sanya/F4-runs-and-progress.md`. Сначала прочитай `AGENTS.md`, `docs/api.md` (п. 5, 6) и `frontend/DESIGN.md` (п. 3, 5).»

## Зачем
Пользователь видит свои прогоны, а во время расчёта — что происходит прямо сейчас. Вкладки результатов до готовности не открываются.

## Что сделать
1. **`/runs`** — таблица прогонов (`GET /api/runs`): id, статус-бейдж (текст + значок + цвет), конфигурация/датасет, создан. Пустой список → `EmptyState` с кнопкой «Новый прогон». Строка кликабельна → `/runs/:id`. Кнопка «Новый прогон» наверху справа (основная).
2. **`/runs/:id`** — шапка прогона: id, датасет, статус, время запуска; справа «Остановить» (пока `pending/running`, `POST …/cancel`) и «Скачать HTML» (только `ready`, ссылка `reportDownloadUrl`). Вкладки «Обзор», «Заявки», «Журнал».
3. Состояние восстанавливается после обновления страницы: всё берётся по `id` из URL.
4. **Вкладка «Журнал»** (`GET /stages`, опрос каждую секунду, пока `pending/running`):
   - 4 этапа вертикальным списком: название, статус (иконка + текст), время начала, длительность;
   - у активного этапа — текст «Нормализуем ответы…» и прогресс `done / total` полосой (только когда `total` известен), иначе индикатор активности;
   - `log` — последние строки этапа, раскрываются по клику; уровни `info/warn/error` разными цветами + значком;
   - при `error`: красный блок «Ошибка выполнения» с `error.message`, отдельно от PASS/FAIL (см. `DESIGN.md` п. 5), кнопка «Повторить запуск» (создаёт новый `POST /api/runs` с тем же `config_id`);
   - `code_ref` показывается подписью «Код: builtin_normalize» (ссылка-открытие кода — после MVP).
5. Вкладки «Обзор» и «Заявки» до `ready` показывают «Отчёт будет доступен после завершения обработки» и ссылку на журнал. Когда статус стал `ready` — сами открывают «Обзор» (если пользователь был на странице расчёта).
6. Опрос не должен жить после ухода со страницы и не должен «мигать» интерфейс (не сбрасывать раскрытые логи при обновлении).

## Готово, когда
Прогон на моках проходит `pending → running → ready`, на нём видно смену этапов и прогресс; остановка работает; перезагрузка страницы не теряет прогон; ошибка запуска (мок с `error`) выглядит как «Ошибка выполнения». Проверено `browser-tester`.
