# F3. Экран «Новый прогон»

**Кто:** Саня · **Ветка:** `front/new-run` · **Папка:** `frontend/` · **Зависит от:** F1, F2

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/sanya/F3-new-run.md`. Сначала прочитай `AGENTS.md`, `docs/api.md` (п. 2, 4, 5) и `frontend/DESIGN.md` (п. 4).»

## Зачем
Первый шаг сценария: выбрать датасет, сохранить конфигурацию, запустить.

## Что сделать (маршрут `/runs/new`)
1. Одна страница с секциями из `DESIGN.md` п. 4. В MVP работают только «Данные», остальное показано честно, но неактивным:
   - **Данные:** название конфигурации (по умолчанию «Прогон на <дата>»), выпадающий список датасетов (`GET /api/datasets`) — после выбора показать: число заявок, срезы `BEFORE (MASTER)` / `AFTER (BETA)`, технические поля. Список «Не сравнивать» (`ignore_paths`) предзаполнен техническими полями датасета, пользователь может убрать/добавить путь текстом;
   - **Обработка:** строки «Приведение ответов», «Сравнение», «Факты» с подписью «Встроенная процедура» и отключённым переключателем «Файл .py / Рабочая область» (подпись «скоро»);
   - **Проверки:** блок с текстом «Проверки подключатся позже» (MVP без них).
2. Кнопки внизу: «Сохранить конфигурацию» (обычная; `POST /api/configs`) и «Запустить» (основная красная; сначала `POST /api/configs`, потом `POST /api/runs` и переход на `/runs/<id>`).
3. Состояния: нет датасетов → `EmptyState` «Положите датасет на сервер»; кнопка «Запустить» неактивна, пока датасет не выбран; во время запросов — блокировка и индикатор; ошибка бэка — `ErrorBox` с `message`.
4. Тело `POST /api/configs` строго по п. 4.2 (`normalize: "builtin_normalize"`, `aggregate: "builtin_aggregate"`, `checks: []`, `array_modes`/`buckets` — значения по умолчанию из ответа/пустые).
5. Клавиатура: форма отправляется Enter, фокус видим, у полей есть подписи.

## Готово, когда
На моках и на настоящем бэке: выбираешь датасет → «Запустить» → попадаешь на `/runs/<id>`. Проверено через `browser-tester`, консоль чистая.
