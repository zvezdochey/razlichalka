# F8. Сквозная проверка, состояния и подгонка под реальный бэк

**Кто:** Саня · **Ветка:** `front/polish` · **Папка:** `frontend/` · **Зависит от:** F3–F7; настоящий бэк (S5–S7)

**Запуск в новом чате:** «Выполни задачу из `docs/tasks/sanya/F8-polish-e2e.md`. Сначала прочитай `AGENTS.md`, `docs/api.md` и `frontend/DESIGN.md` (п. 11).»

## Зачем
Мок и настоящий бэк всегда немного расходятся. Эта задача убирает расхождения и доводит прототип до показа.

## Что сделать
1. Выключить моки, запустить бэк (`docker compose up` или `uvicorn`) и пройти весь сценарий вручную и через `browser-tester`: новый прогон → журнал → обзор → заявки → панель заявки → «Скачать HTML».
2. Если ответ бэка не совпадает с `docs/api.md` — не подгоняй фронт молча. Запиши расхождение (путь, ожидалось, пришло) и передай Семёну; поправить может быть либо бэк, либо `docs/api.md`.
3. Все состояния из `DESIGN.md` п. 11: пустой список прогонов, ошибка загрузки (кнопка «Повторить»), прогон без различий, фильтр без результатов, неверная конфигурация.
4. Размеры: проверить 1366×768 и 1024 px (меню сворачивается, таблицы прокручиваются внутри, шапка и ключевые колонки закреплены). Фокус и клавиатура: Tab-порядок логичен, Enter/Escape работают.
5. Время отклика: во время расчёта интерфейс не подвисает; запрос списка заявок на 500 строк не блокирует страницу.
6. Кнопка «Скачать HTML» в шапке прогона и ссылка «Открыть отчёт в новой вкладке» (`/api/runs/{id}/report`).
7. Страница `/runs/:id` по ссылке из HTML-отчёта (`{origin}/runs/{id}`) открывается и показывает прогон (проверь с Docker-nginx: SPA-фолбэк).
8. Прогнать `ui-designer` по экранам; затем `code-reviewer-front` перед PR.

## Готово, когда
Нет ошибок в консоли, нет «залипших» спиннеров, весь сценарий проходит на настоящем бэке; список расхождений передан Семёну и закрыт.
