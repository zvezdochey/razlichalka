## Зачем
Сейчас на `main` проверены шаги 1 и 3 (конфигурация, числа в обзоре). Остальные шаги никто не проходил целиком. На защите сценарий идёт по времени (20 минут),
и любой сломанный шаг съедает время остальных.

## Что сделать
Пройти в браузере по `docker compose` (`VITE_USE_MOCKS` не используется, только настоящий бэк), пользователь `demo`:
1. Конфигурация: выбрать датасет, процедуры, проверки, запустить.
2. Журнал этапов во время прогона: прогресс виден, интерфейс отвечает. Переход из журнала в код этапа.
3. Числа на обзоре: 502 и 385.
4. Сводная: раскладка по атрибутам и типам изменения.
5. От числа до заявки и атрибута (список, карточка, сравнение до/после).
6. Отчёт проверок: таблица PASS/FAIL, переход из строки к заявкам.
7. Новая проверка прямо в приложении: написать, применить, увидеть в отчёте.
8. Скачать HTML, открыть файл, перейти из него в приложение.
9. Повторное открытие готового отчёта без пересчёта.

Для каждого шага: скриншот в PR, консоль без ошибок (`browser-tester`). Что не работает — отдельный баг владельцу вкладки, а не правка чужой папки.

## Готово, когда
В PR таблица «шаг → да/нет → что не так». Шаги 1–9 с «нет» — заведены как баги с названием вкладки.
