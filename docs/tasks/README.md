# План задач на хакатон

Цель — **минимально рабочий прототип** (MVP) к вечеру 7 ноября. Каждая задача — отдельный файл, который
запускается в **новом чате** одной фразой. После всех MVP-задач работает путь:

> выбрал датасет → запустил → видишь журнал этапов → обзор со счётчиками → таблица заявок → атрибуты заявки → скачал HTML-отчёт — всё в Docker.

Ограничения по времени: фичи до **15:00 7 ноября**, последний слив в `main` — **20:30**, STOP CODING — **21:00**.

## Кто за что

| Кто | Роль | Папка | Задачи |
|---|---|---|---|
| **Егор** | бэк: «модули данных», CSV | `backend/pipeline/` | E1–E8 |
| **Семён** | бэк: API, запуски, отчёт, Docker, сборка в `main` | `backend/app/`, Docker | S1–S10 |
| **Саня** | фронт | `frontend/` | F1–F9 |

(В `README.md` и `docs/ai-tools.md` перечислены Стёпа и Илья — обновить состав команды стоит отдельным `docs:`-коммитом.)

Егор пишет **чистые Python-функции «файлы → CSV»**, которые ничего не знают про HTTP. Семён оборачивает их
в API и фоновые запуски. Договор между ними — [CONTRACTS.md](CONTRACTS.md) (форматы CSV, сигнатуры, пути). Договор бэка и фронта — [../api.md](../api.md).

## Как запускать задачу в новом чате

1. `git checkout main && git pull`, затем `git checkout -b <ветка из файла задачи>`.
2. Открыть новый чат в корне репозитория и вставить фразу из начала файла задачи («Выполни задачу из … Сначала прочитай …»).
3. По итогам агент должен запустить тесты/проверку, о которых сказано в «Готово, когда».
4. Бэк: перед PR вызвать `code-reviewer-back` (+ `api-tester` для ручек). Фронт: `browser-tester` → `ui-designer` → `code-reviewer-front`.
5. Коммит `тип: что сделал`, Pull Request, **сливает Семён**. Свои PR Семён просит посмотреть Егора.

## Небольшие дополнения к `docs/api.md`, которые появятся по ходу

Договорённость «формат не меняем молча» соблюдаем: каждый пункт вносит Семён в `docs/api.md` в **той же ветке**, где добавляет ручку, и пишет Сане.

- `GET /api/configs/{id}` (S3);
- формат полного журнала `GET /runs/{id}/stages/{name}/log` (S4);
- `only_diff` и `search` у `GET /runs/{id}/apps/{app_id}/attributes` (S6);
- `checks_fail` в `summary` (S10).

Фронт (F7) использует `only_diff`/`search` в моках сразу; если Семён сделает иначе — Саня подстраивается в F8.

## Главные договорённости, чтобы не разъехаться

- **Витрина — CSV `;` + `utf-8-sig`**, как в `ПАКЕТ/ЗАДАНИЕ/example/`. Один формат на всех этапах.
- **Сравнение — по `VALUE`**, бакеты только для группировки.
- **Массивы — по ключу**, `scoring[].value` — по индексу. Ключи зашиты в E2.
- **Данные организаторов и `ПАКЕТ/` не коммитим.** Тесты — на выдуманных мини-данных, проверки на настоящих — с `skipif`.
- **Эталонные цифры:** 2002 заявки, смена решения у **385** (273 `approve→reject`, 112 `reject→approve`).
