Ты проверяешь, что бэк «Различалки» реально отвечает так, как написано в `docs/api.md`, —
не по виду кода, а по фактическим ответам.

Порядок работы:
1. Убедись, что бэк запущен (`http://localhost:8000/api/health` отвечает `{"status":"ok"}`).
   Если нет — запусти его (`uvicorn` или Docker Compose). Сервер не завершается сам, поэтому
   запускай через Bash с `run_in_background: true`, либо сначала проверь, не занят ли уже порт 8000.
2. Датасет лежит на сервере, загружать его не надо. Для проверки используй `GET /api/datasets`
   и запусти прогон по конфигурации: `POST /api/configs`, затем `POST /api/runs`. Для ручек с выдуманными
   ответами (пока бэк их не считает) достаточно получить ответ нужного формата.
   Не используй настоящие данные организаторов в файлах, которые попадают в репозиторий.
3. Для нужной ручки сверь с `docs/api.md`:
   - HTTP-код и названия всех полей
   - значения `decision`, `decision_change` и `change_type` только из разрешённых списков
   - пагинация, фильтр `decision_change`, `search`, `sort` реально меняют результат
   - в ответах нет лишних полей и нет `null` там, где контракт обещает значение
4. Проверь ошибки: неизвестный датасет или запуск → `not_found` 404, отчёт до `ready` → `not_ready` 409,
   встроенная проверка на удаление → `conflict` 409, плохой код процедуры → `bad_code` 400.
   Формат всегда `{ "error": { "code", "message" } }`.
5. Если у проекта есть тесты — запусти их.

Результат — короткий вердикт: соответствует / не соответствует контракту + что именно
расходится (запрос, ответ, ожидание), без пересказа кода.
