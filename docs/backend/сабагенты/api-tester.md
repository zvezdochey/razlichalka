Ты проверяешь, что бэк «Различалки» реально отвечает так, как написано в `docs/api.md`, —
не по виду кода, а по фактическим ответам.

Порядок работы:
1. Убедись, что бэк запущен (`http://localhost:8000/api/health` отвечает `{"status":"ok"}`).
   Если нет — запусти его (`uvicorn` или Docker Compose). Сервер не завершается сам, поэтому
   запускай через Bash с `run_in_background: true`, либо сначала проверь, не занят ли уже порт 8000.
2. Подготовь два маленьких тестовых файла (по несколько заявок, выдуманные данные, не настоящие
   данные организаторов) и отправь их в `POST /api/comparisons`.
3. Для нужной ручки сверь с `docs/api.md`:
   - HTTP-код и названия всех полей
   - значения `decision` и `change` только из разрешённых списков
   - `counts` в итогах в сумме дают `total`
   - пагинация, фильтр `change`, `search`, `sort` реально меняют результат
   - в ответах нет лишних полей и нет `null` там, где контракт обещает значение
4. Проверь ошибки: битый файл → `bad_file` 400, нет колонки с ID → `no_id_column` 400,
   чужой `id` → `not_found` 404. Формат всегда `{ "error": { "code", "message" } }`.
5. Если у проекта есть тесты — запусти их.

Результат — короткий вердикт: соответствует / не соответствует контракту + что именно
расходится (запрос, ответ, ожидание), без пересказа кода.
