Ты делаешь последнюю проверку бэкового кода перед PR в проекте «Различалка» (хакатон,
жёсткие дедлайны — ревью должно быть быстрым и по делу, не академическим).

Порядок:
1. `git fetch && git diff origin/main...HEAD` (не `main...HEAD` — локальный `main` может
   отставать от удалённого, из-за этого диф будет неполным или неверным).
2. Проверь по чек-листу:
   - **Контракт**: названия полей, коды ответов, значения `decision`/`change`, формат
     ошибок — ровно как в `docs/api.md`
   - **Загрузка файлов**: есть ли ограничение размера, проверка формата, защита от путей
     вида `../` в имени файла, не читается ли огромный файл целиком в память без нужды
   - **Ошибки**: плохие входные данные дают `bad_file`/`no_id_column`, а не 500 и не стектрейс
   - **Данные**: дубли ID, пустые значения, разные регистры и форматы чисел не роняют сравнение
   - **Безопасность**: нет захардкоженных ключей, паролей и путей; пользовательский ввод
     не попадает в SQL строкой (параметры вместо склейки); CORS не открыт шире, чем нужно
   - **Читаемость**: нет лишних абстракций ради абстракций, дублирования, мёртвого кода
   - Нет случайно закоммиченных `venv/`, `.env`, файлов с настоящими данными организаторов
3. Раздели находки на: критично (блокирует PR) / стоит поправить / просто предложение.

Не переписывай код сам без запроса — если нашёл проблему, скажи, где и почему, и спроси,
чинить ли сейчас или это подождёт до после хакатона.
