# Архитектура: опорный план для защиты

Подробное описание финальной реализации — в [пояснительной записке](explanatory-note.md).
Этот файл оставлен как короткий план для двухминутного рассказа на шаге 9 демо.
Инструкция развёртывания находится в [README](../README.md).

## Что сказать за две минуты

1. **Задача.** Сравниваем уже полученные ответы двух версий СПР на одних заявках;
   сами СПР не вызываем. Переходим от общего числа различий к конкретному атрибуту до/после.
2. **Стек.** React / TypeScript — интерфейс, FastAPI — API, pandas — табличный расчёт;
   nginx и Docker Compose — сборка и развёртывание. Выбор и компромиссы —
   [в разделе 2 записки](explanatory-note.md#2-архитектура-и-выбор-компонентов).
3. **Расчёт.** Приведение → сравнение и UNION → факты → проверки.
   Массивы связываем по предметным ключам, где они доступны. `comparison.csv` хранит до/после,
   `union.csv` — значения двух срезов вертикально. Четыре типа изменения и различие
   строк / уникальных заявок — [в разделе 3](explanatory-note.md#3-приведение-сопоставление-и-аналитические-слои).
4. **Расширение.** Процедуры и проверки подключаются конфигурацией. Свой код исполняется
   в дочерних процессах с контрактами и таймаутами; это не полноценная песочница.
   Запуски идут в фоне, журнал доступен во время обработки; готовые результаты сохраняются в томе.
   Служебные ссылки групп хранятся в SQLite, остальные результаты — CSV / JSON.
5. **Скорость и цена.** Прогрев убирает чтение основной витрины с первого пользовательского запроса,
   но увеличивает время готовности и расход памяти. Вертикальный слой загружается лениво.
   Финальный прямой замер: приведение + сравнение с UNION — **28,42 с**;
   вместе с фактами, пятью проверками и прогревом — **46,26 с**.
   Это один запуск на Windows / Python 3.14, без HTTP и браузера;
   [методика и ограничения](explanatory-note.md#6-измерения-и-проверки) обязательны при цитировании чисел.
