# API: договорённость между бэком и фронтом

Это «розетка и вилка». Бэк отдаёт ровно такие ответы, фронт рассчитывает ровно на них.
Хочешь поменять формат — сначала договорись со второй стороной и поправь этот файл.

Это черновик до хакатона. Когда 6 ноября увидим настоящие данные, поля подправим,
но сами ручки, скорее всего, останутся.

Адрес бэка: `http://localhost:8000`. Все ручки начинаются с `/api`.

---

## Главная идея: сравнение как «номерок в гардеробе»

1. Фронт отправляет два файла.
2. Бэк один раз всё считает и выдаёт **номерок** — `id` сравнения.
3. Дальше фронт по этому номерку спрашивает что угодно: итоги, таблицу, причины, графики.

Зачем так: данные могут быть огромными. Считаем один раз, а не при каждом клике.

---

## Общие словари

**Решение** (`decision`) — всегда одно из:

| Значение | Что значит |
|---|---|
| `approve` | одобрено |
| `reject` | отказ |
| `other` | что-то третье (на доработку, ручная проверка и т.п.) |

Бэк сам переводит «одобрено», `APPROVE`, `1` и прочее в эти слова. Фронт видит только их.

**Что случилось с заявкой** (`change`) — всегда одно из:

| Значение | Что значит |
|---|---|
| `same` | ничего не поменялось |
| `approve_to_reject` | было ДА → стало НЕТ |
| `reject_to_approve` | было НЕТ → стало ДА |
| `decision_other` | решение поменялось как-то иначе (например, на `other`) |
| `terms_changed` | решение то же, но поменялись условия (сумма, ставка, лимит) |
| `only_old` | заявка есть только в старой версии |
| `only_new` | заявка есть только в новой версии |

## 1. Проверка, что бэк жив

`GET /api/health`

```json
{ "status": "ok" }
```

---

## 2. Загрузить два файла → получить номерок

`POST /api/comparisons`

Формат: `multipart/form-data`, два поля — `old` и `new` (файлы CSV / JSON / XLSX).

Ответ:

```json
{ "id": "c_7f3a", "status": "processing" }
```

Если данные маленькие, бэк может сразу вернуть `"status": "ready"`.

---

## 3. Итоги сравнения (для счётчиков сверху)

`GET /api/comparisons/{id}`

```json
{
  "id": "c_7f3a",
  "status": "ready",
  "old_name": "version_1.csv",
  "new_name": "version_2.csv",
  "total": 12000,
  "changed": 340,
  "changed_share": 0.028,
  "counts": {
    "same": 11660,
    "approve_to_reject": 210,
    "reject_to_approve": 95,
    "decision_other": 5,
    "terms_changed": 20,
    "only_old": 6,
    "only_new": 4
  }
}
```

`status` бывает: `processing` (ещё считаем), `ready` (готово), `error` (что-то сломалось, см. раздел «Ошибки»).
Пока `processing` — фронт показывает «Считаем…» и спрашивает снова раз в секунду.

## 4. Таблица заявок (по страницам)

`GET /api/comparisons/{id}/rows`

Параметры (все необязательные):

| Параметр | Пример | Что делает |
|---|---|---|
| `change` | `approve_to_reject` | показать только такие. Можно несколько через запятую. `changed` = все, кроме `same` |
| `search` | `Иванов` | поиск по ID и текстовым полям |
| `sort` | `-amount` | сортировка по полю, минус = по убыванию |
| `page` | `1` | номер страницы, с 1 |
| `size` | `50` | строк на странице, максимум 500 |

Ответ:

```json
{
  "page": 1,
  "size": 50,
  "total": 340,
  "rows": [
    {
      "app_id": "5",
      "change": "approve_to_reject",
      "decision_old": "approve",
      "decision_new": "reject",
      "fields": { "name": "Смирнова", "age": 21, "income": 80000, "amount": 1000000 },
      "changed_fields": [],
      "reason": "Возраст меньше 23"
    }
  ]
}
```

- `fields` — данные заявки для показа в таблице.
- `changed_fields` — какие поля отличаются между версиями (если отличаются).
- `reason` — короткая причина одной строкой, или `null`, если не нашли.

---

## 5. Одна заявка подробно (для окна «почему»)

`GET /api/comparisons/{id}/rows/{app_id}`

```json
{
  "app_id": "5",
  "change": "approve_to_reject",
  "old": { "decision": "approve", "age": 21, "income": 80000, "amount": 1000000 },
  "new": { "decision": "reject",  "age": 21, "income": 80000, "amount": 1000000 },
  "changed_fields": ["decision"],
  "reasons": [
    { "text": "Возраст меньше 23", "rule": "min_age", "confidence": "high" }
  ]
}
```

`confidence`: `high` — причина точная (например, есть лог правил), `low` — наша догадка по данным.

---

## 6. Главные причины изменений

`GET /api/comparisons/{id}/reasons`

```json
{
  "reasons": [
    { "text": "Возраст меньше 23", "rule": "min_age", "affected": 210, "share": 0.62 },
    { "text": "Доход ниже 40 000 ₽", "rule": "min_income", "affected": 95, "share": 0.28 }
  ],
  "unexplained": 35
}
```

`unexplained` — сколько изменённых заявок мы не смогли объяснить. Честно показываем жюри.

---

## 7. Кого затронуло (для графиков)

`GET /api/comparisons/{id}/breakdown?by=age`

`by` — поле, по которому группируем: `age`, `income`, `amount`, `region` и т.п.
Числа бэк сам раскладывает по корзинкам.

```json
{
  "by": "age",
  "groups": [
    { "label": "18–22", "total": 1500, "changed": 210 },
    { "label": "23–30", "total": 4000, "changed": 40 },
    { "label": "31+",   "total": 6500, "changed": 90 }
  ]
}
```

Какие поля можно передать в `by` — смотри следующую ручку.

---

## 8. Какие поля вообще есть

`GET /api/comparisons/{id}/fields`

```json
{
  "fields": [
    { "name": "age",    "title": "Возраст", "type": "number" },
    { "name": "income", "title": "Доход",   "type": "money" },
    { "name": "region", "title": "Регион",  "type": "text" }
  ]
}
```

Фронт по этому списку сам строит колонки таблицы и выбор для графика.
Так не надо переписывать фронт, если в данных другие поля.

---

## 9. Скачать результат

`GET /api/comparisons/{id}/export.csv?change=changed`

Отдаёт CSV-файл. Параметр `change` — как в таблице.

---

## Ошибки

Любая ошибка — в одном виде:

```json
{ "error": { "code": "bad_file", "message": "Не получилось прочитать new: это не CSV" } }
```

| `code` | HTTP | Когда |
|---|---|---|
| `bad_file` | 400 | файл не читается или не того формата |
| `no_id_column` | 400 | не нашли, по какому полю склеивать заявки |
| `not_found` | 404 | нет такого сравнения или заявки |
| `internal` | 500 | всё остальное |

Фронт показывает `message` пользователю как есть.

---

## Порядок работы на хакатоне

1. **Первый час:** бэк делает все ручки с **выдуманными** ответами ровно как тут. Фронт сразу работает с ними.
2. **Дальше:** бэк по одной заменяет выдумку на настоящий расчёт. Фронт ничего не замечает.
3. **Минимум для показа:** ручки 2, 3, 4. Остальное — по мере сил, в порядке 6 → 5 → 7 → 8 → 9.
