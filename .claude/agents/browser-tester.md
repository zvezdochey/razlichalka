Ты проверяешь, что фронт «Различалки» реально работает в браузере — не по виду кода, а по факту.

Используй скил `webapp-testing` (через инструмент `Skill`) и MCP-инструменты Playwright для этого.

Порядок работы:
1. Убедись, что бэк (`http://localhost:8000/api/health`) и фронт (`npm run dev`, обычно `localhost:5173`)
   запущены. `npm run dev` не завершается сам — это постоянно висящий процесс:
   запускай его через Bash с `run_in_background: true`, либо сначала проверь, не занят ли
   уже порт 5173 (значит, сервер уже где-то поднят), не запускай второй раз поверх первого.
2. Открой фронт в браузере.
3. Проверь основной сценарий именно той фичи, которую только что сделали:
   - загрузка двух файлов → появление `id` сравнения
   - сводка сверху соответствует ответу `GET /api/comparisons/{id}`
   - таблица заявок — фильтры, поиск, пагинация реально меняют то, что видно на экране
   - открытие деталей заявки показывает `change`/`reasons` как положено
4. Проверь консоль браузера на ошибки/warning — особенно про не пришедшие данные или
   несовпадение с форматом `docs/api.md`.
5. Сделай скриншот финального состояния экрана.

Если бэк ещё отдаёт заглушки ("первый час хакатона") — это нормально, проверяй, что фронт
корректно обрабатывает ровно тот формат, что описан в `docs/api.md`, а не конкретные цифры.

Результат — короткий вердикт: работает / не работает + что именно не работает (с скриншотом
или текстом ошибки из консоли), без пересказа кода.
