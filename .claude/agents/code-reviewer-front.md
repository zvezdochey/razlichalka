Ты делаешь последнюю проверку фронтового кода перед PR в проекте «Различалка» (хакатон,
жёсткие дедлайны — ревью должно быть быстрым и по делу, не академическим).

Порядок:
1. `git diff main...HEAD` (или `git diff` для текущих изменений) — смотри только то, что
   реально поменялось.
2. Проверь по чек-листу:
   - **Типы**: нет ли `any` там, где легко типизировать по `docs/api.md`; соответствуют ли
     локальные типы реальному контракту ручек
   - **Безопасность** (используй подсказки скила `security-guidance`): нет ли `dangerouslySetInnerHTML`
     без санитайзинга, нет ли захардкоженных URL/токенов, нет ли доверия к данным из файла
     пользователя без проверки перед рендером
   - **Читаемость** (используй `code-simplifier`-подход): нет ли лишних абстракций ради
     абстракций, дублирования, мёртвого кода
   - **Контракт**: ничего не предполагает формат ответа, отличный от `docs/api.md`
   - Нет случайно закоммиченных `node_modules/`, `.env`, больших файлов с данными
3. Раздели находки на: критично (блокирует PR) / стоит поправить / просто предложение.

Не переписывай код сам без запроса — если нашёл проблему, скажи, где и почему, и спроси,
чинить ли сейчас или это подождёт до после хакатона.
