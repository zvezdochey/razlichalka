Ответы после первого экрана каждого раздела:

1. Решение сменили **385** заявок: **273** из одобрения в отказ, **112** из отказа в одобрение.
2. Для доли одобрений стало хуже: чистый сдвиг **161** заявки в сторону отказов (`273 − 112`). Влияние на экономику портфеля без сумм и качества клиентов не оценено.
3. Среди смен решения больше случаев с неизменным входом: **логика 218**, входные данные **167**. На Обзоре это ниже сгиба. Верхняя показанная причина отказа — порог `MFO_ZAIMER_2026_LOW` (274 **строки продуктов**, не уникальные заявки); считать её доказанной главной причиной всех 385 смен нельзя.
4. За 10 секунд по первым экранам нельзя уверенно назвать наиболее затронутый клиентский сегмент или продукт: нет готового ранжирования уникальных заявок по сегментам.
5. Тревожный сигнал — **33 FAIL**. Следующий клик — карточка `33` на Обзоре, затем число заявок в строке проверки; для причины смены — вкладка «Причины» в карточке заявки.

**Вердикт за 10 секунд:** одной надёжной фразы с Обзора не получается. Верно: «У 385 заявок решение изменилось; чистый сдвиг — 161 в сторону отказов; 33 результата проверок FAIL». Источник 218/167 и причина/атрибут должны быть видны рядом с главными числами с явной оговоркой о единице счёта (заявки или строки продуктов). Фразу «Бета режет одобрения на 273 заявки» следует уточнить: 273 потеряли одобрение, но 112 его получили.

## 8. Что не проверено и почему

- MCP Playwright в этой среде не стартовал: ожидал Chrome по `/opt/google/chrome/chrome`, установлен Chromium по `/usr/bin/chromium`. Браузерные сценарии проверялись через IAB/CUA и системный Chromium. Не для каждого экрана сохранён скриншот; консоль и сетевые 4xx/5xx просмотрены выборочно, не исчерпывающе.
- `GET /api/datasets` на чистом main отдаёт только `RUN-20260827-0001`. Поэтому `compare`, `dataset_mini`, `run_mini` как готовые варианты выбора недоступны; собственные мини-датасеты проверены через upload.
- Не пройдены все сочетания фильтров/сортировок API и UI, пять типов карточек заявок, полное редактирование конфигурации в UI, переключение светлой/тёмной темы (переключателя не обнаружено), загрузка всех файлов из `ПАКЕТ/ЗАДАНИЕ/example(s)`, полный осмотр ФС после имён `../`.
- Формат XML, ZIP, JSON-массив, кириллица и пробелы в имени дошли до `ready`; 21 МБ, неверное расширение, битый и пустой JSON дали понятные 400. Попытка `../` в multipart/ZIP также дошла до `ready`, но выхода за каталог загрузки не подтверждено, поэтому дефект безопасности не заявлен.
- Без конкурирующей нагрузки получено 11 с без проверок. Чистый одиночный замер с пятью проверками не выполнен; 25–32 с измерены при параллельных запусках.
