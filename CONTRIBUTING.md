# Правила работы с репозиторием

Коротко: **в `main` только рабочий код. Каждый в своей ветке. Заливаем часто и маленькими кусками.**

---

## 1. Ветки

- `main` — то, что мы покажем жюри. Тут всегда должно запускаться.
- Каждый работает в своей ветке. Название: `кто/что-делает`.

  ```
  semyon/upload
  front/table
  back/reasons
  ```

- Одна ветка — одна задача. Сделал → слил в `main` → новая ветка.

## 2. Коммиты

**Часто.** Как только что-то заработало — коммит. Ориентир: хотя бы раз в 30–60 минут.

**Формат сообщения:** `тип: что сделал`

| Тип | Когда |
|---|---|
| `feat` | добавил новое |
| `fix` | починил |
| `style` | поменял внешний вид |
| `docs` | правил тексты, README, api.md |
| `chore` | настройки, Docker, зависимости |

Примеры:

```
feat: загрузка двух CSV на бэке
fix: таблица не падает на пустых данных
style: красные плашки для отказов
chore: добавил duckdb в зависимости
```

Можно по-русски. Главное — чтобы было понятно, что изменилось, без открытия кода.

## 3. Перед тем как залить

1. Забрать свежее: `git pull origin main`
2. Запустить проект и проверить, что он стартует.
3. Только потом `git push`.

## 4. Как попасть в main

- Через Pull Request на GitHub.
- Сливает **капитан**. Так всегда есть один человек, который знает, что сейчас в `main`.
- Ночью можно без долгого ревью, но проект обязан запускаться.

## 5. Никогда

- ❌ `git push --force` в `main`
- ❌ Коммитить `node_modules/`, `venv/`, `.env`
- ❌ Коммитить пароли, токены, ключи от нейросетей
- ❌ Коммитить большие файлы с данными (больше ~10 МБ)
- ❌ Коммитить настоящие данные организаторов, пока не спросили, можно ли. Данные банковские — могут быть секретными.

## 6. Если конфликт

Это когда двое поменяли одно и то же место.

- Не паниковать и не удалять чужое наугад.
- Позвать того, чей код конфликтует, и решить вместе.
- Если совсем непонятно — `git merge --abort` и звать капитана.

## 7. Финиш (8 ноября)

- **С 18:00** — новые фичи не добавляем. Только чиним и проверяем.
- **20:30** — последний слив в `main`. Капитан ставит метку:
  ```
  git tag final && git push origin final
  ```
- **21:00** — STOP CODING. Сдаём то, что под меткой `final`.
